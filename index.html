The workflow

Four steps. Explicit handoffs.

Use Railspike alongside your assistant's plan mode when you want plans preserved as committed files, explicit approvals, and implementation stages verified and committed one at a time.

  1. 01 / ASSESS (optional)

    Assess the options

    Compare approaches, expose tradeoffs, and choose a direction when the answer is uncertain.

  2. 02 / DEFINE

    Describe the feature

    Capture the problem, user stories, requirements, risks, and a clear completion boundary.

  3. 03 / PLAN

    Plan the stages

    Break the feature into small stages with dependencies and an explicit verification plan.

  4. 04 / IMPLEMENT

    Build and verify

    Work on a feature branch. Verify each stage and commit it with its updated summary.

Each planning step waits for your explicit approval. After reviewing its artifact, type Approved Step N with the step number to proceed. After you approve Step 3, the assistant creates a feature branch and commits the approved plans before implementation. If scope changes, return to planning.

Get started

One submodule.
Your existing assistant.

Use Railspike with an assistant that can read your project files, such as Claude Code, GitHub Copilot, or Codex.

Check these in your project before running the command:

A submodule pins the instructions to a specific revision and lets you review upstream updates without managing a copied set of files.

The instructions live in the submodule. Your feature plans belong in your project's docs/plans/.

1. Add Railspike

git submodule add https://github.com/gulkily/railspike.git docs/railspike

Review and commit .gitmodules and the submodule pointer.

2. Give your assistant a feature

As a user, I would like to export my saved searches as CSV. Please write Step 1 of @railspike.

Select RAILSPIKE.md if autocomplete offers it, or reference docs/railspike/RAILSPIKE.md directly.

3. Review, then approve

Read the artifact before replying Approved Step 1. Continue through the approval loop. For straightforward work, you can start at Step 2.

When to use it

When reviewability is worth the extra step.

Use Railspike for feature work with meaningful scope, decisions, or recovery paths. The approval loop adds overhead and can be excessive for a trivial edit. It helps structure engineering judgment; the quality of the decisions still depends on you and your assistant.
