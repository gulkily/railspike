Railspike

Make your coding agent write the plan down first.

Railspike is a set of Markdown instructions your agent follows. The agent writes requirements and a staged plan into your repo, then stops until you approve each one. After that it works on a branch, one stage at a time, verifying and committing each stage with a record of what changed.

Use it with Claude Code, Codex, GitHub Copilot, or another agent that can read your project files. There is no CLI and there are no runtime dependencies; installation and updates use Git.

Install

From the root of a clean Git working tree:

git submodule add https://github.com/gulkily/railspike.git docs/railspike

Review and commit .gitmodules and the submodule pointer. Then give your agent a task:

I want to export my saved searches as CSV. Write Step 1 of @railspike.

Open the file the agent wrote in docs/plans/, edit it or ask for changes, and when it says what you want, reply Approved Step 1. Repeat for each step. The quick start has the full walkthrough.

The recommendation

## Recommendation
Choose **Option A** as one bounded documentation-only feature: complete diagnostic reports in `{feature_name}_debug_log.md`, with at most one short link line in each completed-step conversation. Required useful/redundant groups, source references, evidence, suggestions, and any inapplicable/uncertain findings belong in the log only. Do not narrate diagnostic collection or echo empty groups in chat.

Keep exceptions narrow: briefly disclose log-write failures or request genuinely necessary mode-state clarification; provide findings in chat when explicitly requested. Ordinary task updates, blockers, and approval requests remain available. Instruction reprints are a separate source of conversation volume and are outside this debug-specific change.

The reply Approved Step 1 is typed in the conversation and is not stored in a file. Steps 2 and 3 follow the same way; after Approved Step 3 the plans are committed first and then each stage gets its own commit:

68663ca docs: organize approved quiet debug mode plans
d84023f docs(stage 1): keep debug reports in Markdown logs
4b36f75 docs(stage 2): explain quiet debug handoffs and recovery

Browse them in the feature folder or the first stage commit.
